# Занятие 4. HTTP-методы, REST и CRUD

## Что вы должны понять

На прошлом занятии веб-приложение впервые получало данные с сервера:

```text
GET → JSON → state → render() → DOM
```

Теперь нужно перейти от простого чтения данных к их изменению.

К концу занятия вы должны понимать:

- что такое ресурс в HTTP API;
- чем отличаются `GET`, `POST`, `PATCH` и `DELETE`;
- что обычно называют CRUD;
- как передать JSON в теле запроса;
- зачем нужен заголовок `Content-Type`;
- почему после ответа сервера нужно обновлять состояние приложения;
- чем код ответа `200` отличается от `201`, `204`, `400`, `404`;
- как проверить каждый запрос через DevTools → Network.

---

## 1. От чтения данных к изменению

В третьей работе использовался запрос:

```text
GET /users
```

Он только получает данные.

Но обычное приложение должно уметь выполнять четыре базовые операции:

```text
Create  — создать
Read    — прочитать
Update  — изменить
Delete  — удалить
```

Первые буквы образуют сокращение:

```text
CRUD
```

Часто CRUD сопоставляют с HTTP-методами:

| Операция | HTTP-метод | Пример |
|---|---|---|
| Create | POST | `POST /posts` |
| Read | GET | `GET /posts` |
| Update | PATCH / PUT | `PATCH /posts/5` |
| Delete | DELETE | `DELETE /posts/5` |

---

## 2. Ресурс и URL

В API обычно работают не с отдельными HTML-страницами, а с ресурсами.

Например:

```text
/posts
```

можно понимать как коллекцию публикаций.

Один конкретный ресурс:

```text
/posts/5
```

— публикация с идентификатором `5`.

Для работы будем использовать учебный сервис JSONPlaceholder:

```text
https://jsonplaceholder.typicode.com
```

Список публикаций:

```text
GET https://jsonplaceholder.typicode.com/posts
```

Чтобы не загружать все записи, можно использовать параметр запроса:

```text
GET https://jsonplaceholder.typicode.com/posts?_limit=10
```

---

## 3. GET — получение данных

Пример:

```javascript
const response = await fetch(
  'https://jsonplaceholder.typicode.com/posts?_limit=10'
);

if (!response.ok) {
  throw new Error(`HTTP ${response.status}`);
}

const posts = await response.json();
```

После преобразования JSON `posts` становится обычным JavaScript-массивом.

---

## 4. POST — создание ресурса

Чтобы создать новую публикацию, отправляем `POST`.

Кроме URL нужно передать настройки запроса:

```javascript
const response = await fetch(
  'https://jsonplaceholder.typicode.com/posts',
  {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      title: 'Новая запись',
      body: 'Текст записи',
      userId: 1
    })
  }
);
```

Здесь появляются три новых элемента.

### method

```javascript
method: 'POST'
```

указывает HTTP-метод.

### Content-Type

```text
Content-Type: application/json
```

сообщает серверу, что тело запроса содержит JSON.

### body

`fetch` не отправляет JavaScript-объект напрямую.

Поэтому:

```javascript
JSON.stringify(object)
```

преобразует объект в JSON-строку.

---

## 5. Ответ на POST

После создания сервер обычно возвращает созданный объект.

Например:

```json
{
  "title": "Новая запись",
  "body": "Текст записи",
  "userId": 1,
  "id": 101
}
```

Часто код ответа при создании:

```text
201 Created
```

После ответа недостаточно просто вывести `console.log()`.

Нужно изменить состояние приложения:

```text
POST
 ↓
ответ сервера
 ↓
state.posts
 ↓
render()
```

---

## 6. PATCH — частичное изменение

Если нужно изменить отдельные поля существующего ресурса:

```text
PATCH /posts/5
```

Пример:

```javascript
const response = await fetch(
  'https://jsonplaceholder.typicode.com/posts/5',
  {
    method: 'PATCH',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      title: 'Изменённый заголовок'
    })
  }
);
```

`PATCH` обычно означает частичное изменение.

Например, можно изменить только `title`, не отправляя заново весь объект.

---

## 7. PATCH и PUT — не одно и то же

Упрощённо:

```text
PATCH → изменить часть ресурса
PUT   → заменить ресурс целиком
```

На практике конкретный API может задавать свои правила.

В этой лабораторной используйте `PATCH`.

---

## 8. DELETE — удаление

Пример:

```javascript
const response = await fetch(
  'https://jsonplaceholder.typicode.com/posts/5',
  {
    method: 'DELETE'
  }
);
```

После успешного ответа нужно удалить запись и из локального состояния:

```javascript
state.posts = state.posts.filter(post => post.id !== id);
```

И снова вызвать:

```javascript
render();
```

---

## 9. Почему state всё ещё нужен

Сервер и DOM не должны становиться двумя независимыми источниками данных.

Используем ту же схему, что и раньше:

```text
HTTP
 ↓
ответ
 ↓
state
 ↓
render()
 ↓
DOM
```

Например, при удалении плохой вариант:

```text
нажали "Удалить"
→ просто удалили карточку из HTML
```

Тогда DOM изменился, но данные в `state.posts` остались прежними.

Лучше:

```text
DELETE
→ успешный ответ
→ изменить state.posts
→ render()
```

---

## 10. Форма и валидация

Для создания и редактирования записи используйте форму.

Минимальные поля:

- заголовок;
- текст.

Пример проверки:

```javascript
const title = titleInput.value.trim();
const body = bodyInput.value.trim();

if (!title || !body) {
  // показать ошибку
  return;
}
```

Не отправляйте заведомо пустые данные на сервер.

---

## 11. Состояние операции

Теперь одного `isLoading` для первоначальной загрузки может быть мало.

Например:

```javascript
const state = {
  posts: [],
  isLoading: false,
  isSaving: false,
  error: null,
  editingId: null
};
```

`editingId` позволяет понять, создаёт пользователь новую запись или редактирует существующую.

Например:

```text
editingId = null
→ создание

editingId = 7
→ редактирование записи 7
```

---

## 12. Учебный API и важное ограничение

JSONPlaceholder — учебный сервис.

Он принимает `POST`, `PATCH` и `DELETE` и возвращает правдоподобные ответы, но **реально не сохраняет изменения в базе**.

Поэтому:

- запрос нужно действительно отправить;
- ответ нужно проверить в Network;
- после успешного ответа локальное состояние приложения нужно обновить самостоятельно;
- после полной перезагрузки страницы тестовые изменения исчезнут.

Это нормально для данной лабораторной.

# Практическая работа №4. CRUD-интерфейс для публикаций

Создайте папку:

```text
internet-technologies/04/
```

Минимальная структура:

```text
index.html
style.css
app.js
README.md
```

---

## Часть 1. Загрузка публикаций

При открытии страницы или по кнопке загрузите:

```text
GET https://jsonplaceholder.typicode.com/posts?_limit=10
```

Сохраните результат в:

```javascript
state.posts
```

Для каждой публикации покажите:

- `id`;
- `title`;
- `body`;
- кнопки `Редактировать` и `Удалить`.

---

## Часть 2. Создание

Добавьте форму:

```text
Заголовок
Текст
[Сохранить]
```

Если новая запись создаётся, отправьте:

```text
POST /posts
```

с JSON-телом.

После успешного ответа добавьте возвращённый объект в `state.posts` и обновите интерфейс.

Пустые поля отправлять нельзя.

---

## Часть 3. Редактирование

При нажатии `Редактировать`:

1. заполните форму текущими значениями;
2. сохраните `id` редактируемой записи;
3. измените подпись кнопки, например на `Сохранить изменения`.

После отправки выполните:

```text
PATCH /posts/:id
```

После успешного ответа обновите соответствующий объект в `state.posts`.

---

## Часть 4. Отмена редактирования

Добавьте кнопку:

```text
Отмена
```

Она должна:

- очистить форму;
- сбросить `editingId`;
- вернуть приложение в режим создания новой записи.

---

## Часть 5. Удаление

При нажатии `Удалить` выполните:

```text
DELETE /posts/:id
```

Только после успешного ответа удалите запись из `state.posts`.

---

## Часть 6. Состояния интерфейса

Пользователь должен видеть:

- первоначальную загрузку;
- ошибку загрузки;
- выполнение сохранения;
- ошибку сохранения или удаления.

Во время активного сохранения нельзя молча создавать несколько одинаковых запросов быстрыми повторными нажатиями.

---

## Часть 7. Network

В DevTools → Network найдите и покажите минимум четыре запроса:

```text
GET
POST
PATCH
DELETE
```

Для каждого посмотрите:

- Request URL;
- Request Method;
- Status Code;
- Request Payload — если он есть;
- Response.

---

## Часть 8. Фильтрация

Добавьте поиск по:

- `title`;
- `body`.

Фильтрация должна выполняться по уже загруженному `state.posts`, без нового запроса при каждом введённом символе.

---

## Требования к структуре кода

Разделите код минимум на функции:

```javascript
async function loadPosts() {}
async function createPost(data) {}
async function updatePost(id, data) {}
async function deletePost(id) {}

function getFilteredPosts(posts, filter) {}
function renderPosts(posts) {}
function render() {}
function resetForm() {}
```

Не выполняйте весь CRUD внутри одного обработчика кнопки.

## Главное после занятия

В третьей работе цепочка была:

```text
GET → данные → state → render
```

Теперь она расширилась:

```text
действие пользователя
        ↓
HTTP-метод
        ↓
ответ сервера
        ↓
изменение state
        ↓
render()
```

Интерфейс не должен изменять данные «сам по себе»: сначала выполняется операция, затем результат отражается в состоянии приложения.
