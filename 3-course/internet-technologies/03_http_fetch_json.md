# Занятие 3. HTTP, Fetch API и работа с JSON

## Что вы должны понять

На прошлых занятиях данные находились прямо внутри JavaScript-программы.

В реальном веб-приложении данные часто приходят извне: с сервера, из API или другого сетевого ресурса.

На этом занятии нужно понять:

- что происходит при HTTP-запросе;
- чем запрос отличается от ответа;
- что такое URL, метод и код состояния;
- что такое JSON;
- почему сетевой запрос выполняется не мгновенно;
- как работают `fetch()` и `async/await`;
- как отображать состояния загрузки и ошибки;
- как увидеть запрос в DevTools → Network;
- как связать полученные данные с уже знакомой схемой «состояние → render → интерфейс».

---

## 1. Клиент и сервер

Браузер — клиент.

Когда веб-приложению нужны данные, оно может отправить запрос серверу.

Упрощённо:

```text
браузер
   |
   | HTTP-запрос
   v
сервер
   |
   | HTTP-ответ
   v
браузер
```

Например, браузер может запросить список пользователей:

```text
GET /users
```

Сервер возвращает ответ:

```text
200 OK
Content-Type: application/json
```

и данные.

---

## 2. HTTP-метод и код состояния

Для чтения данных чаще всего используется метод:

```text
GET
```

На следующих занятиях встретятся и другие методы:

- `POST` — создать данные;
- `PUT/PATCH` — изменить;
- `DELETE` — удалить.

Часто встречающиеся коды ответа:

- `200` — запрос выполнен успешно;
- `201` — ресурс создан;
- `400` — ошибка в запросе;
- `404` — ресурс не найден;
- `500` — ошибка на стороне сервера.

Важно: сам факт того, что `fetch()` завершился, ещё не означает, что сервер ответил `200`.

---

## 3. JSON

Один из самых распространённых форматов обмена данными — JSON.

Пример:

```json
{
  "id": 1,
  "name": "Leanne Graham",
  "email": "leanne@example.com"
}
```

Массив объектов:

```json
[
  {
    "id": 1,
    "name": "Anna"
  },
  {
    "id": 2,
    "name": "Max"
  }
]
```

После преобразования JSON в JavaScript мы снова работаем с обычными массивами и объектами.

---

## 4. Первый запрос через fetch

В работе будем использовать учебный API JSONPlaceholder:

```text
https://jsonplaceholder.typicode.com/users
```

Минимальный запрос:

```javascript
fetch('https://jsonplaceholder.typicode.com/users')
  .then(response => response.json())
  .then(data => {
    console.log(data);
  });
```

Но для дальнейшего кода удобнее использовать `async/await`.

---

## 5. async/await

Пример:

```javascript
async function loadUsers() {
  const response = await fetch(
    'https://jsonplaceholder.typicode.com/users'
  );

  const users = await response.json();

  console.log(users);
}
```

`await` означает: дождаться результата асинхронной операции внутри `async`-функции.

Пока сеть отвечает, браузер не должен «замораживать» всю страницу.

---

## 6. Проверка ответа

Хороший вариант должен проверить код ответа:

```javascript
async function loadUsers() {
  const response = await fetch(
    'https://jsonplaceholder.typicode.com/users'
  );

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  const users = await response.json();

  return users;
}
```

Если запрос закончился кодом `404` или `500`, программа должна это обработать.

---

## 7. Ошибки и try/catch

Сетевой запрос может не выполниться:

- нет сети;
- адрес неправильный;
- сервер недоступен;
- сервер вернул ошибку;
- данные имеют неожиданный формат.

Используйте `try/catch`:

```javascript
async function loadUsers() {
  try {
    // запрос
  } catch (error) {
    console.error(error);
  }
}
```

Ошибка должна быть видна не только в Console, но и пользователю на странице.

---

## 8. Состояние приложения

На втором занятии состояние хранилось в массиве.

Теперь состояние может выглядеть так:

```javascript
const state = {
  users: [],
  isLoading: false,
  error: null,
  filter: ''
};
```

Это позволяет описать несколько состояний интерфейса:

```text
данных ещё нет
загрузка
успешный ответ
ошибка
фильтрация
```

---

## 9. Одна функция render

Как и раньше, интерфейс должен строиться из состояния:

```text
state
  ↓
render()
  ↓
DOM
```

Например:

```javascript
function render() {
  if (state.isLoading) {
    // показать "Загрузка..."
    return;
  }

  if (state.error) {
    // показать ошибку
    return;
  }

  // показать пользователей
}
```

Сетевой код получает данные и изменяет состояние.  
`render()` отвечает только за отображение.

## 10. DevTools → Network

Откройте:

```text
DevTools → Network
```

После запроса найдите строку `users`.

Посмотрите:

- Request URL;
- Request Method;
- Status Code;
- Response Headers;
- Response / Preview;
- время выполнения запроса.

Нужно научиться отличать ошибку JavaScript от проблемы самого HTTP-запроса.

## Часть 1. Загрузка данных

При нажатии кнопки `Загрузить` выполните запрос:

```text
GET https://jsonplaceholder.typicode.com/users
```

Полученный массив пользователей сохраните в состоянии приложения.

Не создавайте карточки пользователей прямо внутри функции запроса.

---

## Часть 2. Состояния интерфейса

На странице должны быть предусмотрены состояния:

1. данные ещё не загружены;
2. идёт загрузка;
3. данные успешно получены;
4. произошла ошибка.

Во время загрузки пользователь должен видеть сообщение:

```text
Загрузка...
```

При ошибке — понятное сообщение.

---

## Часть 3. Вывод пользователей

Для каждого пользователя выведите минимум:

- имя;
- username;
- email;
- город;
- название компании.

Не вставляйте готовую строку HTML для всего приложения одним большим `innerHTML`.

Разбейте создание интерфейса на понятные функции.

Например:

```javascript
function createUserCard(user) {}
function renderUsers(users) {}
function render() {}
```

---

## Часть 4. Фильтрация

Добавьте поле поиска.

Фильтр должен работать минимум по:

- имени;
- username;
- email.

Исходный массив пользователей не изменяйте.

Получайте отфильтрованный набор из исходного состояния.

Например:

```javascript
function getFilteredUsers(users, filter) {
  // вернуть новый массив
}
```

## Часть 6. Обработка ошибки

Проверьте программу с заведомо неправильным адресом, например временно заменив endpoint.

Интерфейс не должен зависать в состоянии `Загрузка...`.

После проверки верните правильный адрес.
