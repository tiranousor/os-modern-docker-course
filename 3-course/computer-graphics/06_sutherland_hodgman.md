# Занятие 6. Отсечение многоугольников: алгоритм Сазерленда–Ходжмана

## О занятии

В ЛР4 отсекались отдельные отрезки прямоугольным окном. Теперь исходным объектом будет целый многоугольник.

Если просто отсечь каждое его ребро отдельно, можно получить набор видимых отрезков, но не новый замкнутый контур. Для дальнейшей заливки и обработки нужен именно список вершин результирующего многоугольника.

Алгоритм Сазерленда–Ходжмана последовательно пропускает многоугольник через каждую границу окна:

~~~text
исходный многоугольник
        ↓
LEFT
        ↓
RIGHT
        ↓
TOP
        ↓
BOTTOM
        ↓
результат
~~~

После каждого этапа получается новый список вершин. В этой работе окно отсечения прямоугольное и, следовательно, выпуклое.

---

# 1. Обработка одной границы

Сначала рассматриваем только одну границу, например:

~~~text
x = xmin
~~~

Последовательно берём каждое ребро многоугольника:

~~~text
S → P
~~~

где S — предыдущая вершина, P — текущая.

Для каждой точки определяем, находится она внутри допустимой полуплоскости или снаружи.

---

# 2. Четыре возможных перехода

Для ребра S → P существует всего четыре случая.

| S | P | Что записать в результат |
|---|---|---|
| inside | inside | P |
| inside | outside | точку пересечения |
| outside | inside | точку пересечения, затем P |
| outside | outside | ничего |

Это основа всего алгоритма.

Важно: inside/outside определяется относительно одной текущей границы, а не сразу всего окна.

---

# 3. Почему правила именно такие

## inside → inside

Ребро остаётся в допустимой области. Текущая вершина P сохраняется.

## inside → outside

Ребро выходит из окна. Видимая часть заканчивается в точке пересечения с границей. Поэтому добавляется только пересечение.

## outside → inside

Ребро входит в окно. Сначала появляется точка пересечения, затем внутренняя вершина P. В результат записываются обе.

## outside → outside

Относительно текущей границы весь рассматриваемый участок находится снаружи. Ничего не добавляется.

---

# 4. Проверка inside для прямоугольника

В Canvas ось Y направлена вниз.

Для окна:

~~~text
xmin
xmax
ymin
ymax
~~~

условия такие:

~~~text
LEFT:   x >= xmin
RIGHT:  x <= xmax
TOP:    y >= ymin
BOTTOM: y <= ymax
~~~

Каждый этап использует только одно из этих условий.

---

# 5. Пересечение с вертикальной границей

Пусть ребро:

~~~text
A(x1, y1)
B(x2, y2)
~~~

Его параметрическая форма:

~~~text
x = x1 + t(x2 - x1)
y = y1 + t(y2 - y1)
~~~

Для вертикальной границы:

~~~text
x = xBoundary
~~~

получаем:

~~~text
t = (xBoundary - x1) / (x2 - x1)
~~~

Затем:

~~~text
y = y1 + t(y2 - y1)
~~~

Реализация:

~~~javascript
function intersectVertical(a, b, xBoundary) {
  const t =
    (xBoundary - a.x) /
    (b.x - a.x);

  return {
    x: xBoundary,
    y: a.y + t * (b.y - a.y)
  };
}
~~~

---

# 6. Пересечение с горизонтальной границей

Для:

~~~text
y = yBoundary
~~~

получаем:

~~~text
t = (yBoundary - y1) / (y2 - y1)
x = x1 + t(x2 - x1)
~~~

Реализация:

~~~javascript
function intersectHorizontal(a, b, yBoundary) {
  const t =
    (yBoundary - a.y) /
    (b.y - a.y);

  return {
    x: a.x + t * (b.x - a.x),
    y: yBoundary
  };
}
~~~

---

# 7. Функция обработки одной границы

Удобно отделить общую логику от конкретной стороны прямоугольника.

~~~javascript
function clipAgainstBoundary(
  polygon,
  isInside,
  getIntersection
) {
  const output = [];

  if (polygon.length === 0) {
    return output;
  }

  let s = polygon[polygon.length - 1];

  for (const p of polygon) {
    const sInside = isInside(s);
    const pInside = isInside(p);

    if (sInside && pInside) {
      output.push(p);
    } else if (sInside && !pInside) {
      output.push(getIntersection(s, p));
    } else if (!sInside && pInside) {
      output.push(getIntersection(s, p));
      output.push(p);
    }

    s = p;
  }

  return output;
}
~~~

Почему начальная S — последняя вершина?

Потому что многоугольник замкнут, и первое проверяемое ребро должно соединить:

~~~text
последнюю вершину → первую
~~~

---

# 8. Последовательная обработка четырёх сторон

После одной границы выходной массив становится входом для следующей.

~~~javascript
function clipPolygon(polygon, rect) {
  let result = polygon;

  result = clipAgainstBoundary(
    result,
    p => p.x >= rect.xmin,
    (a, b) =>
      intersectVertical(a, b, rect.xmin)
  );

  result = clipAgainstBoundary(
    result,
    p => p.x <= rect.xmax,
    (a, b) =>
      intersectVertical(a, b, rect.xmax)
  );

  result = clipAgainstBoundary(
    result,
    p => p.y >= rect.ymin,
    (a, b) =>
      intersectHorizontal(a, b, rect.ymin)
  );

  result = clipAgainstBoundary(
    result,
    p => p.y <= rect.ymax,
    (a, b) =>
      intersectHorizontal(a, b, rect.ymax)
  );

  return result;
}
~~~

Если после какого-либо этапа массив пуст, видимой части больше нет.

---

# 9. Пример одного перехода

Пусть обрабатывается левая граница:

~~~text
x = 4
~~~

Ребро:

~~~text
S = (2, 3)
P = (8, 7)
~~~

S находится снаружи, P — внутри.

Это случай:

~~~text
outside → inside
~~~

Нужно добавить пересечение и P.

Считаем:

~~~text
t = (4 - 2) / (8 - 2)
  = 2 / 6
  = 1/3
~~~

Тогда:

~~~text
y = 3 + 1/3 · (7 - 3)
  = 4.33...
~~~

Точка пересечения:

~~~text
X = (4, 4.33...)
~~~

В выходной список добавляются:

~~~text
(4, 4.33...)
(8, 7)
~~~

---

# 10. Почему число вершин может увеличиться

Отсечение не означает простое удаление всех внешних вершин.

Граница может пересекать несколько рёбер, и каждое такое пересечение создаёт новую вершину.

Поэтому после этапа вершин может стать:

- меньше;
- столько же;
- больше.

Это нормально: алгоритм строит новый контур.

---

# 11. Полностью невидимый многоугольник

Если после обработки границы:

~~~javascript
result.length === 0
~~~

многоугольник полностью исключён уже обработанными полуплоскостями.

Оставшиеся границы можно не проверять.

---

# 12. Отличие от Коэна–Сазерленда

Коэн–Сазерленд работает с одним отрезком:

~~~text
(x1, y1) → (x2, y2)
~~~

Сазерленд–Ходжман работает со списком вершин:

~~~javascript
[
  { x, y },
  { x, y },
  { x, y }
]
~~~

После каждой границы создаётся новый список.

---

# 13. Ограничение

Классический алгоритм Сазерленда–Ходжмана применяется для выпуклого окна отсечения.

Прямоугольник выпуклый, поэтому в этой работе условие выполняется.

Исходный многоугольник может быть невыпуклым.
