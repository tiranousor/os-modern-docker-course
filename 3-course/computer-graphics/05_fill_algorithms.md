# Занятие 5. Заполнение областей и многоугольников

## Что вы должны понять

До этого мы строили границы объектов:

- отрезок;
- окружность;
- окно отсечения.

Но граница и внутренняя область — разные задачи.

Если построить контур многоугольника, Canvas знает только о пикселях его границы, если мы сами работаем на уровне растра.

Чтобы получить заполненную фигуру, нужно определить, какие пиксели находятся внутри.

На этом занятии рассмотрим два разных подхода:

1. **Flood Fill** — заполнение связной области от начальной точки;
2. **Scanline Fill** — заполнение внутренности многоугольника по строкам растра.

К концу занятия вы должны понимать:

- чем контур отличается от области;
- что означает связность пикселей;
- как работает flood fill;
- почему рекурсивный flood fill может быть опасен;
- что такое сканирующая строка;
- почему пересечения с рёбрами можно попарно соединять;
- какие проблемы возникают в вершинах многоугольника;
- чем flood fill отличается от scanline fill.

---

# 1. Контур ещё не означает заполненную фигуру

Пусть алгоритм Брезенхема построил стороны треугольника:

```text
        *
       * *
      *   *
     *     *
    *********
```

Мы знаем пиксели границы.

Но внутренние пиксели:

```text
        *
       *#*
      *###*
     *#####*
    *********
```

нужно определить отдельно.

Есть два принципиально разных способа.

---

# 2. Подход 1: заполнение от внутренней точки

Представим замкнутую область:

```text
************
*          *
*    X     *
*          *
************
```

Точка `X` находится внутри.

Можно начать с неё и распространять цвет на соседние пиксели, пока не встретится граница.

Это идея **Flood Fill**.

---

# 3. Связность пикселей

У пикселя есть соседи.

## 4-связность

```text
    N
    |
W - X - E
    |
    S
```

Используются:

```text
(x + 1, y)
(x - 1, y)
(x, y + 1)
(x, y - 1)
```

## 8-связность

Дополнительно используются диагонали:

```text
NW  N  NE
 W  X  E
SW  S  SE
```

В этой лабораторной для основного flood fill используйте **4-связность**.

---

# 4. Простейшая идея Flood Fill

Псевдокод:

```text
положить стартовый пиксель в очередь

пока очередь не пуста:
    взять пиксель

    если он уже обработан:
        пропустить

    если это граница:
        пропустить

    закрасить его

    добавить 4 соседей
```

Важно отслеживать обработанные пиксели.

Иначе одни и те же точки будут постоянно добавляться повторно.

---

# 5. Почему лучше не начинать с рекурсии

Интуитивная реализация:

```javascript
function fill(x, y) {
  fill(x + 1, y);
  fill(x - 1, y);
  fill(x, y + 1);
  fill(x, y - 1);
}
```

кажется простой.

Но большая область может привести к слишком глубокой рекурсии и переполнению стека вызовов.

Поэтому для учебной реализации удобно использовать явную структуру данных:

```text
stack
```

или:

```text
queue
```

Например:

```javascript
const stack = [{ x: startX, y: startY }];

while (stack.length > 0) {
  const point = stack.pop();

  // проверка
  // закраска
  // добавление соседей
}
```

---

# 6. Что считается границей

Если работа выполняется на логической сетке, удобно хранить состояние отдельно от Canvas.

Например:

```javascript
const grid = [];
```

или двумерный массив:

```text
0 — пусто
1 — граница
2 — заполнено
```

Тогда алгоритм работает с данными, а Canvas только отображает их.

Это надёжнее, чем каждый раз пытаться определять цвет пикселя визуально с Canvas.

---

# 7. Пример Flood Fill

Есть область:

```text
000000000
011111110
010000010
010000010
011111110
000000000
```

где:

```text
1 — граница
0 — свободная клетка
```

Старт:

```text
(3, 2)
```

После заполнения:

```text
000000000
011111110
012222210
012222210
011111110
000000000
```

Алгоритм не должен перейти через клетки `1`.

---

# 8. Когда Flood Fill удобен

Flood fill хорош, когда:

- есть замкнутая граница;
- известна внутренняя стартовая точка;
- нужно заполнить связанную область.

Например:

- инструмент «заливка» в графическом редакторе;
- заполнение области одинакового цвета;
- поиск связной компоненты.

Но для многоугольника есть другой подход, где стартовая точка вообще не нужна.

---

# 9. Scanline Fill

Представим горизонтальную строку пикселей:

```text
-------------------------- y = const
```

Она пересекает многоугольник.

Например:

```text
        /\
-------/--\-------
      /    \
     /______\
```

Сканирующая строка входит в многоугольник в одной точке и выходит в другой.

Значит промежуток между этими точками можно заполнить.

---

# 10. Главная идея scanline

Для каждой целой координаты `y`:

1. найти пересечения строки `y = const` со всеми рёбрами;
2. получить их `x`;
3. отсортировать `x`;
4. соединить пересечения попарно.

Например:

```text
x = 5
x = 12
x = 20
x = 27
```

Заполняем:

```text
[5 ... 12]
[20 ... 27]
```

Почему попарно?

Потому что при движении слева направо мы чередуем:

```text
снаружи
→ внутри
→ снаружи
→ внутри
→ снаружи
```

---

# 11. Пересечение строки с ребром

Пусть ребро:

```text
A(x1, y1)
B(x2, y2)
```

Нужно найти `x`, где оно пересекает строку с координатой `y`.

Используем линейную интерполяцию:

```text
x = x1 + (y - y1) * (x2 - x1) / (y2 - y1)
```

Это та же идея параметрического движения вдоль отрезка, которая уже встречалась при отсечении.

---

# 12. Какие рёбра пересекают строку

Ребро участвует, если сканирующая строка проходит между его концами.

Но есть важная проблема: вершина принадлежит сразу двум рёбрам.

Если бездумно учитывать обе границы включительно, одно пересечение можно посчитать дважды.

Удобное правило:

```text
yMin <= y < yMax
```

То есть нижнюю/начальную границу диапазона включаем, верхнюю — нет.

В системе Canvas названия «нижняя» и «верхняя» могут быть визуально непривычными, поэтому проще думать именно через:

```text
min(y1, y2) <= y < max(y1, y2)
```

---

# 13. Горизонтальные рёбра

Если:

```text
y1 === y2
```

ребро горизонтальное.

При поиске пересечений его обычно не добавляют как отдельное пересечение.

Иначе можно получить неоднозначности и двойной подсчёт.

Горизонтальные стороны всё равно визуально будут частью контура, но для списка пересечений scanline их удобно пропустить.

---

# 14. Базовый алгоритм Scanline Fill

Пример:

```javascript
function getIntersections(points, y) {
  const xs = [];

  for (let i = 0; i < points.length; i += 1) {
    const a = points[i];
    const b = points[(i + 1) % points.length];

    if (a.y === b.y) {
      continue;
    }

    const yMin = Math.min(a.y, b.y);
    const yMax = Math.max(a.y, b.y);

    if (y < yMin || y >= yMax) {
      continue;
    }

    const x =
      a.x +
      ((y - a.y) * (b.x - a.x)) /
        (b.y - a.y);

    xs.push(x);
  }

  xs.sort((a, b) => a - b);

  return xs;
}
```

После этого:

```javascript
for (let i = 0; i < xs.length; i += 2) {
  const xStart = Math.ceil(xs[i]);
  const xEnd = Math.floor(xs[i + 1]);

  for (let x = xStart; x <= xEnd; x += 1) {
    putPixel(x, y, 'fill');
  }
}
```

---

# 15. Почему используются ceil и floor

Пересечение может быть вещественным:

```text
x = 5.3
```

Логический пиксель имеет целую координату.

Если область начинается после `5.3`, первый подходящий целый `x`:

```text
ceil(5.3) = 6
```

Если заканчивается на:

```text
12.8
```

последний целый:

```text
floor(12.8) = 12
```

---

# 16. Flood Fill и Scanline решают похожую задачу по-разному

## Flood Fill

Нужно:

- иметь стартовую точку;
- знать, где граница;
- распространяться по соседям.

Схема:

```text
seed
 ↓
соседи
 ↓
соседи соседей
 ↓
пока не встретили границу
```

## Scanline

Нужно:

- иметь список вершин многоугольника;
- пересекать его горизонтальными строками.

Схема:

```text
polygon
 ↓
y = const
 ↓
пересечения
 ↓
сортировка
 ↓
заполнение пар интервалов
```

Один подход работает как поиск по области.

Другой использует геометрию границы.

# Практическая работа №5. Заполнение областей

Создайте:

```text
computer-graphics/05/
```

Можно использовать Canvas, сетку, `putPixel()` и построение рёбер из предыдущих работ.

---

## Часть 1. Логическая сетка

Используйте логический растр, где каждый пиксель хорошо виден.

Рекомендуемый размер:

```text
40 × 30
```

или больше.

Храните состояние растра отдельно от Canvas.

Например:

```javascript
const grid = ...
```

Canvas должен отображать состояние, а не быть единственным хранилищем данных.

---

## Часть 2. Контур

Создайте замкнутый контур.

Можно:

- задавать список вершин;
- строить стороны алгоритмом Брезенхема.

Минимум один контур должен быть невыпуклым.

Например:

```text
        *
       / \
  *---*   \
  |        *
  *-------*
```

---

## Часть 3. Flood Fill

Реализуйте:

```javascript
floodFill(startX, startY)
```

Требования:

- 4-связность;
- нельзя выходить за границы сетки;
- нельзя проходить через контур;
- нельзя бесконечно обрабатывать один пиксель;
- использовать stack или queue;
- не использовать готовую заливку Canvas.

Стартовую точку можно задавать кликом мыши.

---

## Часть 4. Пошаговый режим Flood Fill

Добавьте режим, позволяющий увидеть распространение заливки.

Не обязательно делать настоящую анимацию.

Можно после выполнения сохранить:

- порядок посещения;
- номер шага для каждой клетки;

и затем отображать первые `N` шагов ползунком или кнопками.

Цель — увидеть, что flood fill работает как обход связной области.

---

## Часть 5. Scanline Fill

По тому же многоугольнику реализуйте:

```javascript
scanlineFill(points)
```

Для каждой строки:

1. найдите пересечения;
2. отсортируйте их;
3. заполните интервалы попарно.

Готовые функции Canvas:

```text
fill()
ctx.fill()
```

для выполнения алгоритма использовать нельзя.

---

## Часть 6. Таблица одной строки

Для выбранного `y` выведите:

```text
y
пересечения X
интервалы заполнения
```

Например:

```text
y = 12
X: 4.5, 11.2, 18.0, 26.7
fill: 5..11, 18..26
```

Это нужно, чтобы был виден ход scanline-алгоритма.

## Часть 8. Сравнение

Для одного и того же многоугольника сравните два метода.

Зафиксируйте:

- количество закрашенных пикселей;
- число обработанных элементов/шагов;
- время выполнения серии запусков через `performance.now()`.

Не делайте вывод по одному запуску.

Главная задача — сравнить не только скорость, но и принцип работы.

Ответьте в выводе:

- когда нужен seed;
- какой метод использует геометрию многоугольника;
- что произойдёт при разрыве контура;
- почему результаты на границе могут немного зависеть от правила округления.

## Главное после занятия

Контур и внутренняя область — разные объекты растровой графики.

Flood Fill отвечает на вопрос:

```text
какие пиксели связаны с этой стартовой точкой
и не отделены границей?
```

Scanline отвечает на другой вопрос:

```text
где горизонтальная строка входит в многоугольник
и где выходит из него?
```

Оба алгоритма дают заполненную область, но приходят к ней совершенно разными способами.
