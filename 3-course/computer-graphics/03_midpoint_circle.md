# Занятие 3. Растеризация окружности: алгоритм средней точки

## Что вы должны понять

На прошлых занятиях мы строили отрезки:

- ЦДА — через вещественные приращения и округление;
- Брезенхем — через накопленную ошибку и выбор следующего пикселя.

Теперь ту же идею дискретного выбора применим к окружности.

К концу занятия вы должны понимать:

- почему нельзя просто «нарисовать формулу окружности» на растровом экране;
- как использовать симметрию окружности;
- почему достаточно вычислять только одну восьмую часть;
- как выбирается следующий пиксель;
- что означает решающая переменная;
- как из одной вычисленной точки получить восемь симметричных;
- чем алгоритм отличается от `ctx.arc()`.

---

## 1. Математическая окружность

Окружность с центром `(cx, cy)` и радиусом `r` описывается:

```text
(x - cx)^2 + (y - cy)^2 = r^2
```

Можно выразить `y`:

```text
y = sqrt(r^2 - x^2)
```

и перебирать `x`.

Но такой подход требует:

- квадратного корня;
- вещественных вычислений;
- округления;
- отдельного решения вопроса, какие пиксели выбирать.

Для растра можно действовать иначе.

---

## 2. Симметрия окружности

Если для окружности с центром в начале координат найдена точка:

```text
(x, y)
```

то ей соответствуют ещё семь точек:

```text
( x,  y)
( y,  x)
(-x,  y)
(-y,  x)
( x, -y)
( y, -x)
(-x, -y)
(-y, -x)
```

Поэтому достаточно вычислять только одну восьмую окружности.

Остальные точки получаются симметрией.

---

## 3. Перенос к центру окружности

Если центр находится в `(cx, cy)`, добавляем координаты центра:

```javascript
function plot8(cx, cy, x, y) {
  putPixel(cx + x, cy + y);
  putPixel(cx + y, cy + x);

  putPixel(cx - x, cy + y);
  putPixel(cx - y, cy + x);

  putPixel(cx + x, cy - y);
  putPixel(cx + y, cy - x);

  putPixel(cx - x, cy - y);
  putPixel(cx - y, cy - x);
}
```

На некоторых шагах часть этих точек может совпадать. Это нормально.

---

## 4. Какие два варианта следующего пикселя рассматриваем

Начинаем сверху:

```text
x = 0
y = r
```

и постепенно увеличиваем `x`.

Пока строится одна восьмая окружности, на каждом шаге выбираем:

1. оставить `y` тем же;
2. уменьшить `y` на 1.

Условно:

```text
E   = (x + 1, y)
SE  = (x + 1, y - 1)
```

Нужно определить, какой вариант лучше соответствует идеальной окружности.

---

## 5. Функция окружности

Используем функцию:

```text
F(x, y) = x² + y² - r²
```

Если:

```text
F(x, y) = 0
```

точка лежит точно на математической окружности.

Если значение отличается от нуля, оно показывает, с какой стороны от границы находится выбранная точка.

В алгоритме средней точки не нужно каждый раз вычислять квадратные корни.

---

## 6. Решение через среднюю точку

Между кандидатами `E` и `SE` рассматривается **средняя точка**.

Для текущей базовой точки `(x, y)` два кандидата имеют координаты:

```text
E  = (x + 1, y)
SE = (x + 1, y - 1)
```

Средняя точка между ними:

```text
M = (x + 1, y - 1/2)
```

Подставляем её в функцию окружности:

```text
F(x, y) = x² + y² - r²
```

Если значение в средней точке отрицательное, середина находится внутри окружности и выбирается `E`.

Если значение неотрицательное, выбирается `SE`.

---

### 6.1. Откуда берётся начальное значение `d = 1 - r`

В начале алгоритма:

```text
x = 0
y = r
```

Первый выбор будет между:

```text
E  = (1, r)
SE = (1, r - 1)
```

Средняя точка между ними:

```text
M₀ = (1, r - 1/2)
```

Вычислим значение функции окружности:

```text
p₀ = F(1, r - 1/2)
```

Подставляем:

```text
p₀ = 1² + (r - 1/2)² - r²
```

Раскрываем квадрат:

```text
(r - 1/2)² = r² - r + 1/4
```

Получаем:

```text
p₀ = 1 + r² - r + 1/4 - r²
```

`r²` сокращаются:

```text
p₀ = 5/4 - r
```

Это точное значение для midpoint-формы, но оно дробное.

Чтобы перейти к целочисленным вычислениям, удобно вычесть постоянную `1/4`:

```text
d = p - 1/4
```

Тогда:

```text
d₀ = (5/4 - r) - 1/4
d₀ = 1 - r
```

Поэтому в программе используется:

```javascript
let d = 1 - r;
```

Вычитание постоянной `1/4` не меняет выбор ветви: для целых `x`, `y` и `r` midpoint-значения имеют вид «целое + 1/4», поэтому проверка `d < 0` даёт тот же выбор, что и точная проверка `p < 0`.

---

### 6.2. Почему при выборе `E` прибавляется `2x + 3`

Пусть на текущем шаге проверяется midpoint:

```text
Mₖ = (x + 1, y - 1/2)
```

Если выбрали `E`, координата `y` не меняется.

На следующем шаге новая средняя точка:

```text
Mₖ₊₁ = (x + 2, y - 1/2)
```

Найдём, насколько изменилось значение функции окружности:

```text
pₖ₊₁ - pₖ =
F(x + 2, y - 1/2) - F(x + 1, y - 1/2)
```

Части с `y` и `r` одинаковые и сокращаются:

```text
pₖ₊₁ - pₖ = (x + 2)² - (x + 1)²
```

Раскрываем квадраты:

```text
(x + 2)² = x² + 4x + 4
(x + 1)² = x² + 2x + 1
```

Вычитаем:

```text
pₖ₊₁ - pₖ =
x² + 4x + 4 - x² - 2x - 1
```

Получаем:

```text
pₖ₊₁ - pₖ = 2x + 3
```

Следовательно:

```text
pₖ₊₁ = pₖ + 2x + 3
```

Так как `d` отличается от `p` только на постоянную `1/4`, для `d` приращение точно такое же:

```text
dₖ₊₁ = dₖ + 2x + 3
```

Отсюда строка программы:

```javascript
d += 2 * x + 3;
```

Важно: здесь используется **старое значение `x`**, а `x += 1` выполняется после обновления `d`.

Если сначала увеличить `x`, та же формула будет записана иначе.

---

### 6.3. Почему при выборе `SE` прибавляется `2(x - y) + 5`

Если выбирается `SE`, меняются обе координаты:

```text
x → x + 1
y → y - 1
```

Текущий midpoint:

```text
Mₖ = (x + 1, y - 1/2)
```

После перехода `SE` следующий midpoint будет:

```text
Mₖ₊₁ = (x + 2, y - 3/2)
```

Снова найдём разность:

```text
pₖ₊₁ - pₖ =
F(x + 2, y - 3/2) - F(x + 1, y - 1/2)
```

Разделим изменение на две части.

По `x`:

```text
(x + 2)² - (x + 1)² = 2x + 3
```

По `y`:

```text
(y - 3/2)² - (y - 1/2)²
```

Раскрываем:

```text
(y - 3/2)² = y² - 3y + 9/4
(y - 1/2)² = y² - y + 1/4
```

Вычитаем:

```text
(y - 3/2)² - (y - 1/2)² =
-2y + 2
```

Складываем обе части:

```text
pₖ₊₁ - pₖ =
(2x + 3) + (-2y + 2)
```

Получаем:

```text
pₖ₊₁ - pₖ = 2x - 2y + 5
```

или:

```text
pₖ₊₁ - pₖ = 2(x - y) + 5
```

Поэтому:

```javascript
d += 2 * (x - y) + 5;
y -= 1;
```

После этого, как и в первой ветви, увеличивается `x`.

---

### 6.4. Что важно увидеть в этих формулах

Алгоритм не пересчитывает каждый раз:

```text
x² + y² - r²
```

с нуля.

Он хранит предыдущее значение `d` и знает, **на сколько оно изменится при переходе к следующей точке**.

Поэтому вместо квадратов и квадратного корня остаются простые операции:

```text
сложение
вычитание
сравнение
```

Начальные значения:

```javascript
let x = 0;
let y = r;
let d = 1 - r;
```

Пока:

```text
x <= y
```

строится одна восьмая окружности.

---

## 7. Алгоритм

```javascript
function circleMidpoint(cx, cy, r) {
  let x = 0;
  let y = r;
  let d = 1 - r;

  while (x <= y) {
    plot8(cx, cy, x, y);

    if (d < 0) {
      d += 2 * x + 3;
    } else {
      d += 2 * (x - y) + 5;
      y -= 1;
    }

    x += 1;
  }
}
```

Здесь используются только:

- сложение;
- вычитание;
- умножение на 2;
- сравнение;
- целочисленные координаты.

---

## 8. Что означает d

`d` — не «ошибка программы».

Это решающая величина, по которой определяется, нужно ли уже уменьшить `y`.

Если:

```text
d < 0
```

выбираем вариант, в котором `y` пока остаётся прежним.

Если:

```text
d >= 0
```

окружность уже достаточно изменила направление, поэтому уменьшаем `y`.

Это та же общая идея, которую вы видели у Брезенхема для отрезка:

```text
не вычислять точную вещественную координату
→ хранить дискретную ошибку/решающую величину
→ по ней выбирать следующий пиксель
```

---

## 9. Почему условие x <= y

Мы строим только сектор от верхней точки примерно до направления 45°.

На границе этого сектора:

```text
x = y
```

После этого следующие точки уже являются отражением тех, которые мы построили раньше.

Продолжать вычисления нет смысла.

---

## 10. Пример вручную

Пусть:

```text
r = 5
```

Начало:

```text
x = 0
y = 5
d = 1 - 5 = -4
```

Первый набор точек строится для:

```text
(0, 5)
```

Так как:

```text
d < 0
```

`y` пока не меняется.

После обновления:

```text
d = -4 + 2·0 + 3 = -1
x = 1
```

Следующая базовая точка:

```text
(1, 5)
```

На каждом шаге полезно выводить таблицу:

```text
шаг | x | y | d до шага | решение | d после шага
```

## Часть 7. Сравнение с вычислением по формуле

Реализуйте второй учебный способ:

```text

```

Достаточно построить с его помощью один сектор и затем использовать ту же симметрию.

Для нескольких радиусов сравните:

- набор полученных пикселей;
- количество вычисленных базовых точек;
- время серии построений через `performance.now()`.

Не делайте вывод по одному запуску.

Главная задача — увидеть разницу между:

```text
формула + sqrt + округление
```

и:

```text
решающая переменная + целочисленные обновления
```

## Главное после занятия

При растеризации окружности не обязательно вычислять каждую точную координату через квадратный корень.

Можно:

```text
вычислить одну восьмую
→ на каждом шаге выбрать один из двух соседних пикселей
→ использовать решающую величину
→ восстановить остальные точки симметрией
```

Это продолжает основную идею растровых алгоритмов: непрерывный математический объект преобразуется в последовательность дискретных решений.
