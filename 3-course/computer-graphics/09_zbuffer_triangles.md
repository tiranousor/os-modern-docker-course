# Занятие 9. Закрашенные 3D-модели: треугольники, видимость и Z-буфер

## О занятии

В ЛР8 мы получили изображение 3D-каркаса: задали вершины, рёбра, матрицы 4×4, камеру, ортографическую и перспективную проекции. Но в каркасном изображении видны даже те рёбра, которые должны находиться за поверхностями объекта.

Теперь научимся строить **непрозрачную закрашенную модель**. Для этого нужны грани, треугольники, растеризация и проверка глубины.

Продолжаем проект из ЛР8: HTML + JavaScript + Canvas. Без Three.js, WebGL и готовых 3D-движков. Математика, растеризация и Z-буфер — собственные.

---

# 1. От рёбер к граням

В ЛР8 куб хранился как массив вершин \`vertices\` и массив пар индексов \`edges\`.

Но рёбра не определяют, какая часть поверхности закрывает другую. Нужны **грани** — участки поверхности, ограниченные вершинами.

Для растеризации удобно представлять каждую грань треугольниками: любые три неколлинеарные точки задают плоский треугольник.

Например, квадратная грань из вершин \`0,1,2,3\` разбивается так:

~~~javascript
const triangles = [
  [0, 1, 2],
  [0, 2, 3]
];
~~~

Два треугольника вместе покрывают квадрат. Для куба из шести квадратных граней получится двенадцать треугольников.

**Важно:** порядок индексов определяет ориентацию грани (winding). Нормали и отсечение обратных граней должны использовать одно последовательное соглашение.

# 2. Этапы построения заполненного объекта

~~~text

            ↓
модельная матрица 4×4
            ↓

            ↓

~~~

В ЛР8 мы сразу рисовали линии через \`ctx.lineTo()\`. Теперь нужно определить, **какие пиксели принадлежат треугольнику**, и сравнить глубину каждого кандидата с уже нарисованными поверхностями.

# 3. Что такое растеризация треугольника

Пусть три проецированные вершины:

~~~text
A = (40, 30)
B = (170, 50)
C = (90, 150)
~~~

Сначала берём ограничивающий прямоугольник (bounding box):

~~~javascript
const minX = Math.floor(Math.min(a.x, b.x, c.x));
const maxX = Math.ceil(Math.max(a.x, b.x, c.x));
const minY = Math.floor(Math.min(a.y, b.y, c.y));
const maxY = Math.ceil(Math.max(a.y, b.y, c.y));
~~~

Мы будем перебирать только пиксели в этом прямоугольнике, а не весь Canvas.

Каждый пиксель проверяем по его центру \`(x + 0.5, y + 0.5)\`. Если центр находится внутри треугольника, пиксель — кандидат на закраску.

---

# 4. Проверка принадлежности: барицентрические координаты

Для треугольника \`A,B,C\` и точки \`P\` можно найти веса \`λA, λB, λC\`.

~~~text
P = λA*A + λB*B + λC*C
λA + λB + λC = 1
~~~

Если все три веса неотрицательны (с небольшим допуском), точка внутри треугольника или на его границе.

Вычислим удвоенную ориентированную площадь:

~~~javascript
function edge(a, b, p) {
  return (b.x - a.x) * (p.y - a.y) -
         (b.y - a.y) * (p.x - a.x);
}
~~~

Для определённости вычислим веса через отношение ориентированных площадей:

~~~javascript
function barycentric(a, b, c, p) {
  const area = edge(a, b, c);
  if (Math.abs(area) < 1e-12) return null;

  const wa = edge(b, c, p) / area;
  const wb = edge(c, a, p) / area;
  const wc = edge(a, b, p) / area;

  return { wa, wb, wc };
}
~~~

Если вершины вырождены (лежат на одной прямой), площадь близка к нулю: такой треугольник закрашивать не нужно.

Для учебной реализации допустим тест \`wa >= -eps && wb >= -eps && wc >= -eps\`. На общих границах треугольников возможна двойная проверка пикселя; это не должно ломать результат с Z-буфером.

---

# 5. Почему обычной закраски недостаточно

Представим два треугольника, проекции которых перекрываются:

- красный расположен на глубине \`z = 3\`;
- синий — на глубине \`z = 6\`.

В нашей системе камера находится в начале координат и смотрит вдоль **+Z**, поэтому **меньшее положительное z — ближе к камере**.

Если просто рисовать треугольники друг за другом, результат будет зависеть от порядка отрисовки: последний треугольник перекроет предыдущий, даже если он расположен дальше.

Для правильного выбора видимого пикселя нужен **Z-буфер**.

---

# 6. Z-буфер: отдельная глубина для каждого пикселя

Z-буфер — массив, в котором для каждого экранного пикселя хранится глубина ближайшей уже принятой поверхности.

Для Canvas размером \`width × height\`:

~~~javascript
const depth = new Float64Array(width * height);
depth.fill(Infinity);
~~~

Изначально для всех пикселей записано \`Infinity\`: пока ничего не нарисовано.

Индекс пикселя:

~~~javascript
const index = y * width + x;
~~~

Проверка:

~~~javascript
if (candidateDepth < depth[index]) {
  depth[index] = candidateDepth;
  // записать цвет этого пикселя
}
~~~

Это правило действует в принятой системе координат \`+Z\`: меньшая глубина означает ближе.

Z-буфер нужно **очищать перед каждым новым кадром**, иначе данные прошлого кадра будут влиять на текущую сцену.

---

# 7. Важная тонкость: глубина в перспективе

В ортографической проекции можно линейно интерполировать глубину \`z\` по барицентрическим весам.

Но после **перспективной проекции** обычная интерполяция \`z\` по экранным координатам не даёт правильную глубину 3D-плоскости.

Для нашего простого проектора \`screenX = cx + f*x/z\`, \`screenY = cy - f*y/z\` линейно интерполируется **обратная глубина**:

~~~text
invZ = λA / zA + λB / zB + λC / zC
z = 1 / invZ
~~~

Это важно при пересечении и перекрытии поверхностей.

~~~javascript
function depthAt(weights, a, b, c, perspective) {
  const { wa, wb, wc } = weights;

  if (!perspective) {
    return wa * a.z + wb * b.z + wc * c.z;
  }

  const invZ = wa / a.z + wb / b.z + wc / c.z;
  return 1 / invZ;
}
~~~

Здесь \`a,b,c\` содержат **положительные глубины вершин в системе камеры**, а \`weights\` вычислены по их **экранным проекциям**. Перед перспективным проектированием вершины должны пройти отсечение по ближней плоскости.

# 8. Пиксели Canvas через ImageData

Для попиксельной закраски удобнее создать один буфер кадра:

~~~javascript
const image = ctx.createImageData(width, height);
const pixels = image.data; // RGBA: четыре байта на пиксель

function putPixel(pixels, width, x, y, color) {
  const offset = 4 * (y * width + x);

  pixels[offset] = color[0];     // R
  pixels[offset + 1] = color[1]; // G
  pixels[offset + 2] = color[2]; // B
  pixels[offset + 3] = 255;      // A
}
~~~

Не вызывайте \`ctx.fillRect()\` отдельно для каждого пикселя: это заметно усложнит сравнение алгоритмов и обычно работает медленнее, чем один \`ImageData\`.

Для отображения готового кадра:

~~~javascript
ctx.putImageData(image, 0, 0);
~~~

Перед каждым кадром создайте или очистите цветовой буфер и Z-буфер. Если фон должен быть непрозрачным, заранее заполните цветовые каналы и альфа-канал фоновым цветом.

# 9. Пример растеризации одного треугольника

Ниже учебная функция. Каждая вершина содержит экранные \`x,y\` и глубину \`z\` **до перспективного деления**.

~~~javascript
function rasterTriangle(a, b, c, color, image, depth, perspective) {
  const width = image.width;
  const height = image.height;
  const left = Math.max(0, Math.floor(Math.min(a.x, b.x, c.x)));
  const right = Math.min(width - 1, Math.ceil(Math.max(a.x, b.x, c.x)));
  const top = Math.max(0, Math.floor(Math.min(a.y, b.y, c.y)));
  const bottom = Math.min(height - 1, Math.ceil(Math.max(a.y, b.y, c.y)));

  for (let y = top; y <= bottom; y++) {
    for (let x = left; x <= right; x++) {
      const weights = barycentric(a, b, c, {
        x: x + 0.5,
        y: y + 0.5
      });

      if (!weights) return; // вырожденный треугольник

      const eps = 1e-9;
      if (weights.wa < -eps || weights.wb < -eps || weights.wc < -eps) {
        continue;
      }

      const z = depthAt(weights, a, b, c, perspective);
      if (!Number.isFinite(z) || z <= 0) continue;

      const index = y * width + x;
      if (z < depth[index]) {
        depth[index] = z;
        putPixel(image.data, width, x, y, color);
      }
    }
  }
}
~~~

**Замечание:** для ортографической проекции модель можно показывать с тем же отсечением \`near\`, поэтому видимые z тоже положительны. Функцию можно обобщить на другую систему координат, но при этом изменится и правило сравнения глубин.

Пиксели, принадлежащие точно общей границе соседних треугольников, здесь обрабатываются упрощённо. Для качественного программного рендерера обычно используется единое правило включения граничных пикселей (например, top-left rule), однако оно необязательно для этой лабораторной.

# 10. Из квадратных граней в треугольники

Для куба можно задать шесть граней, каждая — четыре индекса. Например:

~~~javascript
const quads = [
  [0, 3, 2, 1],
  [4, 5, 6, 7],
  [0, 1, 5, 4],
  [3, 7, 6, 2],
  [0, 4, 7, 3],
  [1, 2, 6, 5]
];
~~~

При указанном в ЛР8 порядке вершин этот список задаёт последовательную наружную ориентацию граней.

Каждый четырёхугольник разбиваем на два треугольника:

~~~javascript
const triangles = quads.flatMap(([a, b, c, d]) => [
  [a, b, c],
  [a, c, d]
]);
~~~

Если вершины четырёхугольника не лежат в одной плоскости, выбор диагонали влияет на результат. Для куба этого ограничения нет.

# 11. Отсечение треугольника по ближней плоскости

В ЛР8 мы отсекали **рёбра**, но теперь рисуем заполненные **треугольники**. Нельзя просто отбросить треугольник, если одна вершина оказалась за \`near\`: видимая часть его поверхности должна сохраниться.

Используем отсечение выпуклого многоугольника одной плоскостью \`z >= near\`. На входе три вершины, на выходе может быть:

- ноль вершин — треугольник целиком невидим;
- три вершины — исходный или отсечённый треугольник;
- четыре вершины — отсечённый четырёхугольник, который нужно разбить на два треугольника.

Точка пересечения ребра \`A → B\`:

~~~text
t = (near - A.z) / (B.z - A.z)
P = A + t * (B - A)
~~~

Пример:

~~~javascript
function cutNear(a, b, near) {
  const t = (near - a.z) / (b.z - a.z);
  return {
    x: a.x + t * (b.x - a.x),
    y: a.y + t * (b.y - a.y),
    z: near
  };
}

function clipPolygonNear(vertices, near) {
  const output = [];

  for (let i = 0; i < vertices.length; i++) {
    const a = vertices[i];
    const b = vertices[(i + 1) % vertices.length];
    const insideA = a.z >= near;
    const insideB = b.z >= near;

    if (insideA && insideB) {
      output.push(b);
    } else if (insideA && !insideB) {
      output.push(cutNear(a, b, near));
    } else if (!insideA && insideB) {
      output.push(cutNear(a, b, near), b);
    }
  }

  return output;
}
~~~

Выполняйте отсечение **в координатах камеры до перспективного деления**.

После отсечения многоугольник можно триангулировать «веером» вокруг первой вершины:

~~~javascript
function triangulateFan(points) {
  const result = [];
  for (let i = 1; i + 1 < points.length; i++) {
    result.push([points[0], points[i], points[i + 1]]);
  }
  return result;
}
~~~

# 12. Обратные грани: дополнительная оптимизация

Если объект замкнутый и грани ориентированы согласованно, можно не рисовать грани, направленные от камеры. Это **back-face culling**.

Для треугольника в системе камеры найдём нормаль:

~~~javascript
function cross(u, v) {
  return {
    x: u.y * v.z - u.z * v.y,
    y: u.z * v.x - u.x * v.z,
    z: u.x * v.y - u.y * v.x
  };
}

function normal(a, b, c) {
  const u = { x: b.x - a.x, y: b.y - a.y, z: b.z - a.z };
  const v = { x: c.x - a.x, y: c.y - a.y, z: c.z - a.z };
  return cross(u, v);
}
~~~

Для наружной нормали \`n\` и камеры в начале координат вектор от точки грани к камере равен \`-a\`. Если \`dot(n, -a) <= 0\`, грань обычно является обратной или видимой с ребра и её можно пропустить (с допуском для пограничных случаев).

~~~javascript
function dot(a, b) {
  return a.x*b.x + a.y*b.y + a.z*b.z;
}

function frontFacing(a, b, c) {
  const n = normal(a, b, c);
  return dot(n, { x: -a.x, y: -a.y, z: -a.z }) > 1e-10;
}
~~~

Проверку выполняйте для **согласованно ориентированных** треугольников. Если порядок индексов перепутан, можно случайно скрыть видимые грани.

Back-face culling не заменяет Z-буфер: передние грани разных объектов тоже могут перекрывать друг друга.

# 13. Проверки и анализ корректности

1. Один треугольник полностью внутри Canvas заполняется.
2. Вырожденный треугольник не рисуется.
3. Треугольник, частично выходящий за края Canvas, не вызывает запись за границы буфера.
4. Два перекрывающихся треугольника разного цвета рисуются одинаково независимо от порядка их передачи.
5. В ортографической проекции ближний треугольник закрывает дальний.
6. В перспективной проекции корректно интерполируется глубина через \`1/z\`.
7. Треугольник с одной вершиной за \`near\` правильно отсекается.
8. При вращении куб не превращается в «прозрачный» каркас.
9. Сброс очищает Z-буфер и восстанавливает исходное положение.
10. При включённом/выключенном back-face culling (если реализован) видимое изображение замкнутого куба остаётся тем же, а количество обрабатываемых треугольников может уменьшиться.
