# Занятие 2. Алгоритм Брезенхема для отрезка

## Что вы должны понять

На прошлом занятии мы строили отрезок алгоритмом ЦДА. Он понятный, но использует вещественные вычисления и округление на каждом шаге.

Теперь разберём алгоритм Брезенхема — классический способ растеризации отрезка, в котором решение о следующем пикселе принимается с помощью накопленной ошибки.

К концу занятия вы должны понимать:

- почему вообще понадобился другой алгоритм;
- что означает ошибка в алгоритме Брезенхема;
- как выбирается следующий пиксель;
- как обработать все направления отрезка;
- чем Брезенхем отличается от ЦДА;
- почему одинаковый внешний результат ещё не означает одинаковый алгоритм.

## 1. В чём проблема ЦДА

В ЦДА мы вычисляли:

```javascript
const xStep = dx / steps;
const yStep = dy / steps;
```

а затем на каждом шаге делали примерно следующее:

```javascript
x += xStep;
y += yStep;
putPixel(Math.round(x), Math.round(y));
```

Это работает, но требует операций с вещественными числами и округления.

Алгоритм Брезенхема строит тот же тип объекта — растровый отрезок, — но по другой логике.

---

## 2. Главная идея

Представим, что линия идёт в основном слева направо и её наклон не больше 1.

На каждом шаге по `x` нам нужно выбрать один из двух возможных пикселей:

```text
E  — пиксель справа
NE — пиксель справа и выше
```

Условно:

```text
      NE
     []
[] -> [] E
```

Нужно решить, какой из двух пикселей находится ближе к идеальной математической линии.

Вместо вычисления настоящего расстояния каждый раз можно хранить специальную величину — ошибку.

Если накопленная ошибка становится достаточно большой, алгоритм дополнительно изменяет вторую координату.

---

## 3. Универсальная идея через `dx`, `dy` и направление

Чтобы алгоритм работал не только слева направо, удобно отдельно хранить направление движения.

```javascript
const dx = Math.abs(x2 - x1);
const dy = Math.abs(y2 - y1);

const sx = x1 < x2 ? 1 : -1;
const sy = y1 < y2 ? 1 : -1;
```

`dx` и `dy` — длины изменения координат без знака.

`sx` показывает, куда двигаться по `x`:

```text
+1 — вправо
-1 — влево
```

`sy` делает то же самое для `y`.

---

## 4. Одна из универсальных форм алгоритма

```javascript
function lineBresenham(x1, y1, x2, y2) {
  let x = x1;
  let y = y1;

  const dx = Math.abs(x2 - x1);
  const dy = Math.abs(y2 - y1);

  const sx = x1 < x2 ? 1 : -1;
  const sy = y1 < y2 ? 1 : -1;

  let error = dx - dy;

  while (true) {
    putPixel(x, y);

    if (x === x2 && y === y2) {
      break;
    }

    const error2 = 2 * error;

    if (error2 > -dy) {
      error -= dy;
      x += sx;
    }

    if (error2 < dx) {
      error += dx;
      y += sy;
    }
  }
}
```

Важно не просто переписать этот код, а разобраться, что делает каждая его часть.

---

## 5. Почему здесь две проверки

На некоторых шагах меняется только `x`, на некоторых только `y`, а иногда меняются обе координаты.

Поэтому используются две отдельные проверки:

```javascript
if (error2 > -dy) { ... }
if (error2 < dx) { ... }
```

Если заменить вторую проверку на `else if`, поведение алгоритма изменится.

Это хороший пример того, почему похожий код может решать уже другую задачу.

## 6. Пример вручную

Рассмотрим:

```text
A(2, 2)
B(8, 5)
```

Имеем:

```text
dx = 6
dy = 3
sx = 1
sy = 1
error = 3
```

Начинаем в `(2, 2)`.

Дальше на каждом шаге вычисляется:

```text
error2 = 2 * error
```

и определяется, нужно ли изменить `x`, `y` или обе координаты.

Для понимания алгоритма полезно выводить таблицу:

```text
шаг | x | y | error до шага | error2 | изменился x | изменился y
```

## 7. Граничные случаи

Алгоритм должен работать для всех вариантов:

### Горизонтальный отрезок

```text
(2, 5) -> (20, 5)
```

### Вертикальный

```text
(7, 2) -> (7, 20)
```

### Справа налево

```text
(20, 8) -> (2, 3)
```

### Снизу вверх

```text
(5, 20) -> (15, 2)
```

### Крутой наклон

```text
(3, 2) -> (7, 25)
```

### Одна точка

```text
(10, 10) -> (10, 10)
```

Если реализация работает только для первого октанта, она считается неполной.

## 8. ЦДА и Брезенхем — в чём разница

Оба алгоритма решают одну задачу: выбирают пиксели для изображения отрезка.

### ЦДА

Основная идея:

```text
прибавлять вещественные приращения координат
```

Характерные операции:

- деление;
- вещественные значения;
- округление.

### Брезенхем

Основная идея:

```text
накапливать ошибку и по ней выбирать следующий пиксель
```

Характерные операции:

- сложение и вычитание;
- сравнение;
- целочисленные координаты.

Сегодня на современных компьютерах разница во времени для маленького числа линий может быть незаметной. Но алгоритм Брезенхема важен как пример того, как математическую задачу можно преобразовать в эффективную дискретную процедуру.

Реализуйте функцию:

```javascript
lineBresenham(x1, y1, x2, y2)
```

Не используйте `ctx.lineTo()`.


## Часть 6. Небольшой эксперимент

Постройте большое количество случайных отрезков сначала ЦДА, затем Брезенхемом и измерьте время выполнения через `performance.now()`.

Пример:

```javascript
const start = performance.now();

// серия построений

const end = performance.now();
console.log(end - start);
```

Не делайте вывод о скорости по одному запуску. Выполните несколько запусков и сравните результаты.

Главная цель этого пункта — научиться измерять программу, а не заранее доказать, что один алгоритм обязательно окажется быстрее другого в браузере.

## Главное после занятия

Алгоритм Брезенхема показывает важный принцип компьютерной графики: вместо постоянной работы с непрерывной математической моделью можно поддерживать дискретную величину ошибки и на её основе быстро выбирать следующий пиксель.

Дальше этот подход к пошаговому выбору элементов растра встретится и в других графических алгоритмах.
