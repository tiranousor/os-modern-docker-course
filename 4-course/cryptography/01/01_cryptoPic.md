# Лабораторная работа №1. Шифрование изображений: потоковый метод и AES

## 1. Цель работы

Научиться применять симметричное шифрование к данным изображения и понять разницу между простым потоковым шифрованием и блочным шифром AES.

В этой работе необходимо:

- реализовать собственный простой потоковый шифр на основе XOR и генератора ключевого потока;
- выполнить шифрование изображения с помощью AES;
- сравнить AES-ECB и один из режимов `CBC` или `CTR`;
- обеспечить полное восстановление исходного файла после расшифрования;
- показать, как выбор режима и ключа влияет на результат.

Главная цель — не количество графиков, а понимание того, **что происходит с данными при шифровании и почему разные режимы AES дают разный результат**.

## 3. Часть 1. Собственный потоковый вариант

Реализуйте простой потоковый способ шифрования.

Общая схема:

```text
исходные байты
        +
ключевой поток
        ↓ XOR
зашифрованные байты
```

Для каждого байта:

```text
cipher[i] = plain[i] XOR keystream[i]
```

При повторном XOR с тем же ключевым потоком исходные данные восстанавливаются:

```text
plain[i] = cipher[i] XOR keystream[i]
```

### Требования

1. Получить байты изображения.
2. Самостоятельно реализовать простой генератор псевдослучайной последовательности, например:
   - `xorshift32`;
   - LCG;
   - другой простой генератор после согласования.
3. Начальное состояние генератора должно зависеть от ключа.
4. Сгенерировать ключевой поток нужной длины.
5. Выполнить XOR.
6. Реализовать обратное преобразование.
7. Проверить, что после расшифрования получается исходный файл.

> Это учебный потоковый вариант. Его задача — показать принцип работы ключевого потока. Не нужно доказывать его криптографическую стойкость.

## 4. Часть 2. AES

Для AES разрешено использовать готовую криптографическую библиотеку.

Нужно выполнить шифрование в двух вариантах:

1. **AES-ECB**;
2. **AES-CBC или AES-CTR** — один режим на выбор.

### Что нужно показать

Для одного и того же изображения сравните результаты ECB и выбранного второго режима.

Обратите внимание:

- почему в ECB структура изображения может частично сохраняться;
- почему CBC/CTR скрывает структуру лучше;
- для чего нужен `IV` или `nonce`;
- почему при одном ключе нельзя бездумно повторно использовать тот же `IV/nonce`.

Если используется CBC, необходимо корректно обработать размер блока и padding.

---

## 5. KEY и IV/nonce

Нужно понимать разницу:

- **KEY** — секретный ключ;
- **IV/nonce** — не обязан быть секретным, но должен быть корректно сформирован и сохранён вместе с параметрами шифрования.

При шифровании программа должна либо сама генерировать `IV/nonce`, либо явно получать его как параметр.

При расшифровании должен использоваться тот же `IV/nonce`.

Можно сохранять параметры в `meta.json`, например:

```json
{
  "algorithm": "aes-ctr",
  "nonce": "...",
  "source": "gradient.png"
}
```

Сам ключ в `meta.json` сохранять не нужно.

## 6. Проверка обратимости

Это обязательная часть.

После цепочки

```text
исходное изображение
→ шифрование
→ расшифрование
→ восстановленное изображение
```

исходный и восстановленный файлы должны совпадать.

Проверьте это одним из способов:

- SHA-256 исходного и восстановленного файла;
- побайтовое сравнение.

В отчёте покажите результат проверки.

## 9. Рекомендуемый интерфейс программы

Можно сделать консольную утилиту, например:

```bash
python cryptopic.py encrypt --in gradient.png --out encrypted.bin --algo aes-ctr --key "my-key"
```

и:

```bash
python cryptopic.py decrypt --in encrypted.bin --out restored.png --algo aes-ctr --key "my-key" --meta meta.json
```

Строго повторять этот интерфейс не требуется. Главное — чтобы шифрование и расшифрование можно было однозначно запустить и проверить.
