# Лабораторная работа №2. Стеганография и гибридная защита данных

## 1. Цель работы

В этой лабораторной нужно объединить две идеи:

1. **стеганографию** — скрыть сам факт передачи данных;
2. **шифрование** — скрыть содержание сообщения.

Сначала необходимо реализовать обычный LSB, затем использовать его для сокрытия **уже зашифрованного сообщения**.

Итоговая схема:

```text
исходный текст
      ↓
шифрование
      ↓
ciphertext + служебные данные
      ↓
LSB-встраивание
      ↓
stego.png
```

Обратная схема:

```text
stego.png
      ↓
LSB-извлечение
      ↓
ciphertext + служебные данные
      ↓
расшифрование
      ↓
исходный текст
```

Эта гибридная часть является **завершающей частью лабораторной №2**. Отдельную лабораторную №3 выполнять не требуется.

---

## 2. Краткая теория

### 2.1. Что такое LSB

LSB — Least Significant Bit, младший значащий бит.

Например:

```text
11010010
```

Если нужно встроить бит `1`, можно изменить только последний бит:

```text
11010011
```

Числовое значение изменилось всего на 1, поэтому визуально изменение обычно незаметно.

В RGB-изображении можно использовать младшие биты компонент:

```text
R
G
B
```

# Часть 1. Обычный LSB

## 4. Встраивание сообщения

Реализуйте функцию или режим программы, который получает:

- PNG-изображение;
- текстовое сообщение;

и создаёт новое PNG-изображение со спрятанным сообщением.

Общий принцип:

1. преобразовать текст в байты;
2. байты преобразовать в последовательность битов;
3. последовательно обходить пиксели и цветовые каналы;
4. заменять младший бит компонент изображения битами сообщения;
5. сохранить полученное изображение.

Нельзя использовать готовую библиотеку, которая выполняет LSB-стеганографию целиком.

Библиотеки для чтения и сохранения изображений использовать можно.

---

## 5. Как понять, где заканчивается сообщение

При извлечении программа должна понимать, сколько данных необходимо прочитать.

Рекомендуемый вариант — сохранить длину сообщения в начале скрытых данных.

Например:

```text
[4 байта длины][байты сообщения]
```

Тогда при извлечении:

1. сначала читается длина;
2. затем ровно указанное количество байт.

Можно использовать другой корректный способ, но его нужно уметь объяснить.

---

## 6. Проверка вместимости

До начала встраивания программа должна проверить, помещается ли сообщение в изображение.

Если используется 1 LSB каждого RGB-канала:

```text
capacity_bits = width × height × 3
```

Не забудьте учесть служебные данные, например длину сообщения.

Если данных слишком много, программа должна вывести понятную ошибку, а не создать повреждённый результат.

# Часть 3. Гибридная защита: шифрование + LSB

## 9. Зачем шифровать сообщение перед встраиванием

Обычный LSB скрывает сообщение в изображении, но если злоумышленник знает способ извлечения, он может сразу получить исходный текст.

Поэтому теперь перед встраиванием текст необходимо зашифровать.

Получается:

```text
"секретное сообщение"
        ↓
     AES
        ↓
случайно выглядящие байты
        ↓
      LSB
```

Стеганография и шифрование решают разные задачи:

- шифрование скрывает **содержание**;
- стеганография скрывает **факт передачи**.

---

## 10. Шифрование сообщения

Разрешено использовать криптографическую библиотеку.

Рекомендуемый вариант:

- ключ получать из пароля через **PBKDF2** или другую стандартную KDF;
- использовать AES в безопасном режиме;
- `salt` и `IV/nonce` генерировать случайно.

Можно повторно использовать AES-реализацию и знания из лабораторной №1.

Не нужно самостоятельно реализовывать AES.

### Минимально необходимо сохранить

Чтобы сообщение потом можно было расшифровать, вместе с ciphertext необходимо сохранить служебные данные:

- `salt`, если используется KDF;
- `IV/nonce`;
- длину зашифрованных данных;
- сам ciphertext.

Например, логическая структура скрытого блока может быть такой:

```text
[длина]
[salt]
[IV/nonce]
[ciphertext]
```

Конкретный бинарный формат можно выбрать самостоятельно.

---

## 11. Полный режим encode

Программа должна уметь выполнить всю цепочку:

```text
текст
→ получение ключа из пароля
→ шифрование
→ формирование служебного блока
→ проверка вместимости
→ LSB-встраивание
→ stego.png
```

Пример интерфейса:

```bash
python stegocrypto.py encode   --in cover.png   --message message.txt   --out stego.png   --password "my-password"
```

Строго повторять данный интерфейс не требуется.

---

## 12. Полный режим decode

Обратная цепочка:

```text
stego.png
→ извлечение LSB
→ разбор служебного блока
→ получение ключа из пароля
→ расшифрование
→ recovered.txt
```

Например:

```bash
python stegocrypto.py decode   --in stego.png   --out recovered.txt   --password "my-password"
```

Исходный и восстановленный текст должны совпадать.
